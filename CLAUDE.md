## The prose is final, and it is not this repo's to change

**Every sentence on the page comes from `content/manuscript.md` verbatim.**
That file is the accepted v5 manuscript (2026-10-12) and prose changes go
through Aaron, never through a session. A session may fix a typo and must list

the four author paragraphs, the hook or the bold closing line are missing from

## The experiments

**Expected IDs come from `docs/assets/dispatch-scenario.json` and are never
derived from the query under test.** The displayed SQL is the executed SQL:
`docs/assets/dispatch-code.js` holds both query strings. The defective one
carries two rule mismatches, `>` where the rule says at least (line 7, and
the lesson text names that line) and no clause collapsing repeated IDs; the
correction changes the operator and adds `GROUP BY order_id`, and nothing
else differs (D14). The defective run returns two rows, the expected count,
with the wrong IDs. The check compares IDs and multiplicity, not counts. The defective line is not highlighted until
a run; the correction button is disabled until a run; failed and corrected
runs both stay in the visible history; each experiment resets independently.

**sql.js loads on the first click of the run button, never on page load.**
The vendored engine is the asm.js build (`docs/vendor/sql.js/sql-asm.js`),
chosen so the page also runs from `file://`, which the gate review uses; the
WASM build cannot be fetched from disk. `docs/vendor/sql.js/provenance.json`
records the npm archive integrity and the file hashes. All assets are local;
the page makes no runtime network request except the four Felix font
families from Google Fonts, a collision recorded in the decision record.

## Committing

**Stage by name - never the two blanket forms.** They are denied in
`.claude/settings.json`, and that block does **not** bind under
`bypassPermissions`. What binds is
`.claude/hooks/no_blanket_add_or_force_push.py`, a `PreToolUse` hook, and it
loads only when the session is rooted here.

The git `pre-commit` hook in `.githooks/` runs the credential gate, then the
whitespace gate, and fails closed. **It is inert until
`git config core.hooksPath .githooks` has been run in this clone.** Run
`python .claude/hooks/hook_test_matrix.py` to confirm the guards behave.

This repo's root commit was made from a session rooted at `C:\Projects`, so
the hook-manifest entry in `cascadia-standards/governance/hook_manifest.json`
is owed to a session rooted there and is not written from here.

**Two things that blocked commits on 2026-10-12, both by the gate working as
designed.** First, the hook's shell resolves `python3` before `python`, and on
this machine `python3` is the Microsoft Store alias stub, which prints
"Python was not found" and exits non-zero, so every commit is refused until a
real interpreter is ahead of it: prefix the commit's PATH with
`C:\Users\Ajayr\AppData\Local\Python\bin`. Second, the secret scan's tier-1
AWS-key shape matched a base64 run inside `docs/vendor/sql.js/sql-asm.js`, a
false positive in a compiled blob that is hash-pinned and cannot carry a
pragma; `docs/vendor/.gitattributes` declares that one file binary so the
scanner skips it, and the root `.gitattributes` stays the kit's verbatim
copy. Neither is a reason for `--no-verify`.

A stale `.git/index.lock` is benign: delete it and retry.
